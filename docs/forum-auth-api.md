# API авторизации форума PfauMC — для разработчика Minecraft-плагина

Форум не использует регистрацию по email/паролю: **аккаунт форума — это аккаунт в
игре**. Всё общее — ник из реестра игроков, роли и права из `perms.*`, блокировки
из `punish.*`. Своих пользователей, ролей и банов у форума нет.

## Схема

```
Игрок в игре           Плагин                            Бэкенд
    │                    │                                 │
    │  /auth             │                                 │
    ├───────────────────►│  POST /internal/forum/login-token│
    │                    ├────────────────────────────────►│  создаёт одноразовый токен
    │                    │◄────────────────────────────────┤  { url, token, expires_in }
    │◄───────────────────┤  кликабельная ссылка в чат      │
    │                                                      │
    │  открывает ссылку в браузере ───────────────────────►│  pfaumc.io/auth/game?token=…
    │                                                      │  POST /api/v1/forum/auth/game
    │                                                      │  токен сгорает, ставится сессия
```

> Форум живёт в `pfaumc-backend` (тот же сервис, что и авторизация в игре). Раньше это
> API было на сайте — сайт стал статикой, серверный код переехал сюда.

Токен проверяется **только на сервере**. В клиентском коде сайта нет ни
секретов, ни логики проверки.

## 1. Выдача одноразового токена

```
POST <внутренний адрес бэкенда>/internal/forum/login-token
x-internal-auth: <INTERNAL_API_SECRET>
Content-Type: application/json

{
  "uuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5",
  "name": "Steve"
}
```

Ручка живёт на внутреннем слушателе рядом с остальным `/internal/*`, поэтому
отдельного секрета для форума больше нет — плагин использует тот же
`INTERNAL_API_SECRET`, что и для сессий и наказаний.

| Поле   | Тип    | Обязательно | Формат                                                   |
|--------|--------|-------------|-----------------------------------------------------------|
| `uuid` | string | да          | UUID с дефисами, регистр любой                            |
| `name` | string | да          | `[A-Za-z0-9_]{1,16}` — нужен, только если игрока ещё нет в реестре |

Скин не передаётся: сайт рисует голову по UUID сам.

`uuid` — это тот же идентификатор игрока, что и везде в бэкенде (`gamer.gamer.id`):
UUID аккаунта Mojang, для оффлайн-режима — стабильный оффлайн-UUID сервера.

### Успех — `200 OK`

```json
{
  "url": "https://pfaumc.io/auth/game?token=q0Xk…",
  "token": "q0Xk…",
  "expires_in": 300,
  "expires_at": "2026-08-04T12:34:56.789Z"
}
```

Отправьте игроку в чат `url` (кликабельной ссылкой). `token` отдаётся отдельно,
если нужно собрать ссылку самостоятельно.

### Свойства токена

* случайные 32 байта, `base64url` (≈43 символа);
* в базе хранится **только SHA-256** от токена;
* время жизни — **300 секунд**;
* **одноразовый**: гасится атомарным `UPDATE … WHERE used_at IS NULL` —
  повторное использование невозможно даже при гонке запросов;
* жёстко привязан к переданному UUID.

### Ошибки

| Код   | `code`           | Когда                                                       |
|-------|------------------|-------------------------------------------------------------|
| `400` | `bad_request`    | некорректный `uuid` или `name`                              |
| `401` | —                | нет заголовка `x-internal-auth` или неверный секрет         |
| `429` | `rate_limited`   | больше 5 запросов для одного UUID за минуту                 |
| `503` | —                | на бэкенде не задан `INTERNAL_API_SECRET`                   |
| `500` | `internal`       | внутренняя ошибка                                           |

Тело ошибки всегда: `{ "error": "текст для игрока", "code": "…" }`.

Рекомендация для плагина: при `429` попросить игрока подождать, при `5xx` —
показать «сервис форума временно недоступен» и не спамить повторами.

## 2. Обмен токена на сессию (делает сайт, плагину не нужен)

```
POST https://auth.pfaumc.io/api/v1/forum/auth/game
{ "token": "…", "remember": true }
```

* `410 token_invalid` — токен просрочен, уже использован или не существует;
* при успехе ставится `HttpOnly`-cookie сессии (30 дней при `remember: true`,
  иначе 12 часов) и отдаётся профиль пользователя.

---

## Настройки

Отдельных переменных у форума нет: он использует базу и `INTERNAL_API_SECRET`
бэкенда. Значения зашиты в коде (`src/web/forum.rs`), потому что домен и сервер
у нас одни: ссылка входа ведёт на `https://pfaumc.io`, токен живёт 300 секунд,
«запомнить меня» — 30 дней (иначе 12 часов), пауза между сообщениями — 15 секунд.

---

## Роли и права

Отдельных ролей у форума нет — берутся те же, что и в игре:

* **ярлык роли** рядом с ником — верхняя действующая роль игрока из `perms.role`
  (название и цвет вытаскиваются из её MiniMessage-имени);
* **модерация форума** — роль `helper+` и выше по `perms.role.priority`. Отдельного
  права под форум нет, выдавать ничего не нужно: у кого в игре роль не ниже хелпера,
  тот модерирует и форум;
* **просмотр спрятанных разделов** — порог ниже: роль `helper` или `builder` и выше
  (берётся нижний приоритет из существующих). Стафф читает разделы и категории с
  `is_visible = false` и темы в них, но кнопок модерации не получает и удалённые
  сообщения не видит.

Если ни одной пороговой роли в `perms.role` нет, соответствующее право закрыто для
всех — это единственные точки, от которых считаются пороги.

Блокировка тоже общая: активный `ban` или `mute` из `punish.punishment` закрывает
запись на форуме — писать, реагировать и подписываться нельзя, читать можно.
Причина наказания показывается игроку.

## Пример запроса из плагина (Java, без зависимостей)

```java
var body = """
    {"uuid":"%s","name":"%s"}""".formatted(player.getUniqueId(), player.getName());

var request = HttpRequest.newBuilder(URI.create(backendInternalUrl + "/internal/forum/login-token"))
    .header("x-internal-auth", secret)
    .header("Content-Type", "application/json")
    .timeout(Duration.ofSeconds(10))
    .POST(HttpRequest.BodyPublishers.ofString(body, StandardCharsets.UTF_8))
    .build();

// Ответ: {"url": "...", "expires_in": 300}
// Отправить player.sendMessage(...) со ссылкой url.
```

Запрос обязательно выполнять асинхронно относительно основного потока сервера.
